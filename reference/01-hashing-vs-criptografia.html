01: Criptografia vs. Hashing Seguro

Guia de consulta rápida para o backend e apresentação.

1. O Conceito Fundamental

Característica Criptografia (Cifras) Hashing Unidirecional
Direção Bidirecional (Cifra ⇄ Decifra) Unidirecional (Entrada → Hash fixo, impossível reverter)
Uso de Chave Exige chave simétrica (AES) ou par público/privado (RSA) Algoritmo matemático público; pode usar Salt e Pepper
Objetivo Confidencialidade de dados que precisam ser lidos depois Verificação de integridade e armazenamento seguro de senhas
Exemplos Reais AES-256-GCM, ChaCha20, RSA, TLS 1.3 bcrypt, Argon2id, SHA-256, SHA-3

2. Comparativo de Algoritmos de Hash

Algoritmo Tipo Resistência a GPU/ASIC Adequado para Senhas?
MD5 / SHA-1 Hash Rápido Legado Nenhuma (Colisões conhecidas) ❌ NUNCA (Vulnerável e Obsoleto)
SHA-256 / SHA-3 Hash Criptográfico Rápido Nenhuma (Bilhões de cálculos/s em GPU) ❌ NÃO para senhas (ótimo para checksum de arquivos)
bcrypt KDF (Blowfish-based) Média (Custo de CPU configurável) ✔ SIM (Amplamente adotado e maduro)
Argon2id KDF Moderna (Vencedora PHC) Alta (Memory-Hard: consome RAM e CPU) ✔ RECOMENDAÇÃO OWASP ATUAL

Regra de Ouro do Backend:

Hashes rápidos (SHA-256) foram projetados para serem rápidos. Armazenamento de senhas exige algoritmos propositalmente lentos e gulosos por memória (Argon2id / bcrypt) para inviabilizar ataques de força bruta.
